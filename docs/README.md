# Prompt Architect Studio Docs

This folder is the source of truth for project planning, product strategy, design direction, and implementation notes.

## Current Docs

- `PRODUCT_STRATEGY.md`  
  Defines what the app does, who it is for, why it matters, MVP scope, and design principles.

- `EXECUTION_ENGINE_STRATEGY.md`  
  Captures the shift from prompt consultant to one-click execution engine, including outcome-based labels, style preservation, and model-specific formatting.

- `PROJECT_STRUCTURE.md`  
  Defines where files should live as the project grows.

- `COMPETITOR_RESEARCH.md`  
  Maps prompt-tool categories, competitors, weaknesses, and differentiation opportunities.

- `DESIGN_BRIEF.md`  
  Defines the visual and UX direction before frontend revisions continue.

- `FRONTEND_DESIGN_RESEARCH.md`  
  Captures current SaaS UX research, approachable visual direction, palette usage, object metaphors, and animation guidance for the next frontend redesign.

- `USER_PERSONAS.md`  
  Defines the main end-user types, their goals, frustrations, and success criteria.

- `USER_JOURNEYS.md`  
  Maps the key flows users should be able to complete.

- `ONBOARDING_STRATEGY.md`  
  Defines how the product orients new users without slowing them down.

- `AI_PROMPTING_ORIENTATION.md`  
  Provides the plain-language explanation of prompt architecture used for product copy and onboarding.

- `INFORMATION_ARCHITECTURE.md`  
  Defines page hierarchy, section purpose, and what belongs in the MVP.

- `VISUAL_SYSTEM.md`  
  Defines color, typography, component, layout, and interaction direction.

- `STATE_DESIGN.md`  
  Defines empty, ready, loading, success, error, and validation states.

- `EXAMPLE_PROMPTS.md`  
  Provides persona-aligned starter prompts for onboarding and testing.

- `TRUST_AND_PRIVACY.md`  
  Defines privacy posture, sensitive data guidance, and trust copy requirements.

- `PROMPT_QUALITY_STANDARDS.md`  
  Defines what makes generated prompts useful across frameworks and target models.

- `REFERENCE_ANALYSIS.md`  
  Captures external design inspiration and translates it into product-specific guidance.

- `UX_UI_DIRECTION.md`  
  Defines the recommended page flow, section purpose, interaction direction, and implementation order.

- `DEVELOPMENT_PLAN.md`  
  Defines the phased build plan, acceptance criteria, and next implementation order.

## Recommended Doc Categories

Use these names as the project expands:

- `PRODUCT_STRATEGY.md` - product purpose, audience, positioning, MVP scope.
- `DESIGN_BRIEF.md` - page structure, visual direction, components, copy hierarchy.
- `DEVELOPMENT_PLAN.md` - phases, tasks, acceptance criteria, build order.
- `API_NOTES.md` - endpoint behavior, request/response shape, model integration notes.
- `DEPLOYMENT.md` - Cloudflare Pages settings and release checklist.

## Working Rule

Before making major UI or feature changes, update or create the relevant doc first. The app should be built from the strategy, not from ad hoc design choices.
