# Visual System

## Purpose

This document defines the visual direction for Prompt Architect Studio.

The visual system should make the product feel focused, useful, modern, and lightly distinctive without distracting from the tool.

## Design Personality

Prompt Architect Studio should feel:

- Clear.
- Structured.
- Intelligent.
- Friendly.
- Work-ready.
- Slightly playful in details, not childish.

It should not feel:

- Generic AI gradient.
- Dense enterprise dashboard.
- Crypto/cyberpunk.
- Academic.
- Decorative for its own sake.

## Color Direction

Current approved palette and roles:

### Base

- Sand grid page background.
- Warm paper/cream section surfaces.
- White rough prompt input field to clearly signal the writing area.

### Authority

- Near-black for primary text.
- Dark gray for the full-width footer.

### Intelligence Accent

- Medium blue for outcome-style titles, use-case titles, and selected content emphasis.
- Dark blue for selected prompt-style state.

### Warm Action Accent

- Dark red/coral for primary actions and the Studio headline.
- Cream/yellow for soft footer links and gentle CTA contrast.

### Utility Neutrals

- Teal/celadon accents for workbench panels, helper surfaces, and soft structure.
- Muted gray-green for body copy and secondary UI.

## Final Visual Baseline

The current final version uses the `retro-thumbnail-v3.html` visual treatment merged into the full product layout.

Approved details:

- Retro workbench mood.
- Sand grid page background.
- Rounded warm content panels.
- Sticky-note input panel.
- White textarea for user input.
- Dark red/coral primary action treatment.
- Dark red Studio headline.
- Dark red numbers in the How It Works cards.
- Medium blue framework outcome titles and use-case titles.
- Dark blue selected prompt style state.
- Full-width dark gray footer with reversed text.
- Footer links light yellow and non-bold.

## Color Rules

- Do not let the page become one-note blue or one-note dark.
- Use bright color sparingly.
- CTAs must have strong contrast.
- Output code block should remain highly readable.
- Error, loading, and success states need distinct colors.

## Typography

Recommended direction:

- Sans-serif.
- Strong headline weight.
- Highly readable body copy.
- Monospace for generated prompt output.

Rules:

- Do not use delicate serifs or decorative fonts.
- Do not overuse huge hero type.
- Body text should be easy to scan.
- Form labels should be clear and confident.

## Layout

The app should use:

- A slim hero.
- A clear two-column studio on desktop.
- A stacked layout on mobile.
- Compact supporting sections.

Use cards and tiles only when they structure real information.

## Components

Core components:

- Hero section.
- Textarea.
- Framework selector.
- Model selector.
- Primary button.
- Output code block.
- Copy button.
- Example prompt trigger.
- Context cards.
- Privacy note.

## Interaction Feel

Interactions should be:

- Fast.
- Subtle.
- Predictable.
- Accessible.

Use:

- Clear hover states.
- Clear focus states.
- Copy confirmation.
- Loading state on submit.

Avoid:

- Excessive animation.
- Decorative motion that delays the task.
- Hidden controls.

## Bento Guidance

Bento can be used for product explanation, but only with meaningful tiles.

Allowed:

- Rough input tile.
- Framework tile.
- Model tuning tile.
- Architect rules tile.
- Output tile.

Avoid:

- Random photos.
- Abstract filler.
- Tiles that do not communicate the workflow.

## Mobile

Mobile design must:

- Put the core workflow within easy reach.
- Avoid oversized hero sections.
- Preserve readable output.
- Use tap-friendly controls.
- Stack selectors cleanly.

## Visual Quality Bar

The UI should look like a real SaaS MVP someone could launch, not a demo page.

Polish should show up in:

- Spacing.
- Alignment.
- Input states.
- Empty state copy.
- Copy button behavior.
- Mobile layout.
