# Onboarding Strategy

## Purpose

This document defines how Prompt Architect Studio should orient users without slowing them down.

The product should be usable immediately. Onboarding should be embedded in the interface, not presented as a separate hurdle.

## Onboarding Principle

The best onboarding is a successful first prompt.

Users should learn by doing:

1. Paste rough prompt.
2. Keep Dynamic selected or choose a framework.
3. Select target model.
4. Generate.
5. Copy.

## Recommended MVP Onboarding

### 1. Slim Hero Explanation

The hero should answer:

- What does this app do?
- Why should I care?
- What do I do first?

Suggested structure:

- Headline: “Turn messy ideas into model-ready prompts.”
- Subcopy: “Choose a framework, choose a model, and get a structured prompt you can paste into GPT-5.5, Claude, or Gemini.”
- CTA: “Start architecting”

### 2. Example Prompt

Include a low-friction example prompt action.

Purpose:

- Gives hesitant users an easy way to test the product.
- Demonstrates the kind of input the app expects.
- Reduces blank-page friction.

Guidelines:

- Examples should be work-oriented.
- Avoid gimmicky or overly broad examples.
- Rotate across founder, marketer, consultant, and internal-ops use cases.

### 3. Inline Framework Help

Each framework should include a one-line explanation.

Good:

- “Dynamic adapts the structure to the task when you are not sure which framework fits.”

Avoid:

- Long definitions.
- Academic prompting theory.
- Dense tooltips that hide important context.

### 4. Output Placeholder

Before generation, the output area should explain what will appear there.

Example:

> Your structured prompt will appear here, ready to copy into your target model.

### 5. Context Section Below the Studio

Below the core tool, include a short explainer:

- Why rough prompts fail.
- What frameworks do.
- Why model-aware prompting matters.

This section is optional reading, not required onboarding.

## Introductory Video Consideration

A short intro video could help, but it should not be required.

Recommended format:

- 45 to 75 seconds.
- Screen-led.
- Shows before/after transformation.
- Explains “rough idea → framework → model → copy-ready prompt.”
- No long founder monologue in the MVP.

Possible placements:

- Secondary link in hero: “Watch 60-second demo.”
- Below the studio as a small contextual card.
- Help section after the MVP proves users need it.

Do not place a video where it delays the first action.

## What Not To Do

- No mandatory onboarding modal.
- No multi-step product tour on first load.
- No account creation.
- No full tutorial before the textarea.
- No long “What is prompt engineering?” essay above the tool.

## Future Onboarding Ideas

- Guided first prompt.
- Framework recommendation based on rough input.
- Before/after examples.
- “Best for” labels on framework buttons.
- Sample outputs by role.
- Lightweight help drawer.

## MVP Recommendation

For the first launch, use:

- Slim hero.
- Example prompt button.
- Inline framework explanation.
- Clear output placeholder.
- Short context section below.

Skip the video until the page structure and messaging are stable.
